# Agent Instructions

Repo-wide rules for every coding agent and for people. `CLAUDE.md` only imports this file. Each half of the repo adds its own rules: `server/AGENTS.md` for Python and `client/AGENTS.md` for the web app.

First Domino finds the step where a failed AI agent run went wrong, and proves it by replay.

## Repository layout

```
first-domino/
  AGENTS.md, CLAUDE.md, README.md    repo-wide rules and overview
  docs/                              shared: architecture, contract, decisions, deploy, release
  server/                           Python: API, engine, database, SDK
  client/                          Next.js web app
  .github/workflows/                 server.yml, client.yml and sdk-release.yml (GitHub needs them at the root)
```

## Backend and frontend are separate

- Each half has its own tooling, dependencies, rules, environment file, `.gitignore` and CI workflow. Neither imports, reads or builds files from the other.
- They meet only at the HTTP contract: `docs/CONTRACT.md` is the agreement and `server/api/openapi.json` is generated by the backend. The frontend generates its client from that file (`../server/api/openapi.json`); it is the only backend file the frontend reads.
- Open an agent chat inside the half you work on (`server/` or `client/`), so it loads that half's rules, hooks and skills.

## Changing the contract

- The contract changes through the API and `docs/CONTRACT.md` together, never by editing generated files.
- After an API change: `make openapi` and `make sdk-models` in `server/`, then `bun run generate:api` in `client/`.

## Scope

- Scope decisions favor a working end-to-end product over completeness. Open-source libraries are fine.
- Never copy code, prompts, configuration or text from another company's repository. Write it fresh.
- Never name an employer or its customers in code, docs, commits or public material. Reference products by public names only (LangSmith, Braintrust, Sentry).

## Principles for both halves

- Follow YAGNI and KISS. Build the smallest thing that makes the demo work, then stop.
- Code quality is the default. Others will read this code.
- Never branch on an error message or any human-readable string. Use enums, error codes and typed fields.
- Never edit a generated file. Change the source and regenerate.
- **Follow precedent.** Reuse the pattern that already exists. Deviate only for a concrete reason.
- **Do not restate.** Do not write a rule or comment that a type, a linter, a test or configuration already carries.
- **Document the non-obvious.** Write down exceptions, constraints and decisions, with the reason.
- **Ask when precedent is unclear.** When examples are missing or conflict, ask. Do not invent a convention.
- A comment states the rule or the non-obvious reason. It never narrates the code and never tells a debugging story.
- No secret in code, ever.

## Git

- Never commit, push, branch or open a pull request unless asked.
- Never pass `--no-verify`. Never force-push.
- Commit messages are one line: `type: subject` (`feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`, `perf`). A commit-msg hook checks it.

## Where to read more

- `docs/DECISIONS.md`: what is decided, what is still open, and why.
